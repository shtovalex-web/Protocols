# Автообновление ProtocolOOT

Проверка и установка обновлений для **собранного Windows .exe** (версия **1.5.3** и новее).

## Как это работает

1. При старте `.exe` программа **сканирует каталог шары** (`update_config.json` → путь к каталогу).
2. Ищет релизы в **`windows/<версия>/`** и **`linux/<версия>/`** (`manifest.json` и исполняемый файл).
3. Выбирается **новейшая** версия, которая выше текущей (`APP_VERSION` или `data/update_info.json`).
4. Если версия новее — показывается диалог установки.
5. Новый `.exe` копируется рядом с текущим как `ProtocolOOT.exe.new`, проверяется **размер** и **SHA-256**.
6. Текущий файл переименовывается в `.old`, новый — в рабочее имя.
7. Обновляются файлы из **`data/`** по списку **`data_files`** в manifest (с откатом во временной папке при ошибке).
8. Программа **не перезапускается сама** — показывается сообщение об успехе; пользователь закрывает окно и снова запускает **`ProtocolOOT.exe`**. Список изменений — в `data/.pending_changelog.json`, диалог «Что нового» после открытия главного окна.
9. Ошибки сети или недоступность шары **не блокируют** запуск (тихий старт).

Даже если в корне шары остался старый `manifest.json`, программа найдёт релизы в `windows/<версия>/manifest.json`.

Ручная проверка: **«Справка» → «Проверить обновления…»**.

## Сборка релиза (Windows)

Рекомендуется **Python 3.12** (не 3.14+ — PyInstaller и Tcl/Tk на новых версиях нестабильны):

```text
py -3.12 -m pip install -r requirements-build.txt
py -3.12 build_windows_exe.py "D:\Путь\к\папке\Windows"
```

Результат:

- **`ProtocolOOT.exe`** (onefile), **`data/`** и **`manifest.json`** в выбранной папке;
- публикация на **`D:\Обновление\windows\<версия>/`** (копия exe + data + manifest);
- **`data/update_info.json`** — маркер версии комплекта.

Локальная папка **`UPDATE/`** в репозитории **не используется**.

## Пути по умолчанию

| Что | Значение |
|-----|----------|
| Каталог шары (прод) | `\\tn.tngrp.ru\df\AK\SHR\Distr_О_О\Шитов Алексей Александрович` |
| Локальная тестовая шара | `D:\Обновление` |
| Локальный конфиг | `update_config.json` рядом с `.exe` / в корне проекта |
| Пример манифеста | `docs/update_manifest.example.json` |

## Локальный конфиг `update_config.json`

```json
{
  "manifest_path": "//tn.tngrp.ru/df/AK/SHR/Distr_О_О/Шитов Алексей Александрович",
  "enabled": true
}
```

Поле `manifest_path` — **каталог шары** (рекомендуется) или путь к `manifest.json` (устаревший вариант). В JSON используйте **прямые слэши** (`D:/Обновление`).

## Переменные окружения

| Переменная | Назначение |
|------------|------------|
| `PROTOCOLOOT_UPDATE_MANIFEST` | Путь к манифесту (приоритет над файлом конфигурации) |
| `PROTOCOLOOT_UPDATE_CHECK=1` | Проверять обновления при запуске **из исходников** (для отладки) |

## Формат `manifest.json`

См. `docs/update_manifest.example.json`:

- `latest_version` — версия на шаре (сравнение `major.minor.patch`; `1.5` = `1.5.0`).
- `windows.relative_path` — путь к `.exe` **относительно каталога манифеста** (обычно `ProtocolOOT.exe`).
- `windows.sha256`, `windows.size` — контроль целостности после копирования.
- `changes_short` — пункты для диалога «Что нового».
- `data_files` — список файлов в `data/` (sha256, size, policy `replace`).
- `mandatory` — при `true` диалог «ОК/Отмена» вместо «Да/Нет».

Структура шары:

```text
\\tn.tngrp.ru\df\AK\SHR\Distr_О_О\Шитов Алексей Александрович\
  windows\
    1.5.3\
      manifest.json
      ProtocolOOT.exe
      data\
        default_protocol.docx
        FAQ.txt
        …
```

## Публикация обновления на шару

После сборки `.exe` (или вручную):

```text
py -3.12 tools/publish_update_manifest.py ^
  --exe "D:\ProtocolOHT_onefile\ProtocolOOT.exe" ^
  --version 1.5.3 ^
  --share-root "\\tn.tngrp.ru\df\AK\SHR\Distr_О_О\Шитов Алексей Александрович" ^
  --change "Краткое описание изменения"
```

Скрипт кладёт exe и `data/` в `share-root/windows/<версия>/`, считает SHA-256 и пишет **`manifest.json`** в ту же папку.

## Обновление `data/` (этап 2)

Вместе с exe обновляются файлы из **`data/`** (см. `update_bundle_files.py`):

- `default_protocol.docx`, `default_protocol_tehnicheskiy.docx`
- инструкции `.docx`, `FAQ.txt`, `ЖУРНАЛ_ДОРАБОТОК.md`
- шаблоны Минтруд XSD (`.xlsx`), `icon.ico`

**Не обновляются:** `protocols.db`, Excel в **корне**, `Protokol/`, `Mintrud/`, `update_config.json`.

**`data/update_info.json`** — локальный маркер версии комплекта; пишется при сборке и после обновления, **не входит** в `data_files` на шаре.

Перед заменой каждого файла резервная копия хранится во **временной папке** (не в `data/`). Устаревшие **`*.bak`** в `data/` удаляются при обновлении. Папка **`data.backup/`** не создаётся.

## Локальная тестовая шара

```text
D:\Обновление\
  windows\
    1.5.3\
      manifest.json
      ProtocolOOT.exe
      data\
```

Рядом с `ProtocolOOT.exe`:

```json
{
  "manifest_path": "D:/Обновление",
  "enabled": true
}
```

Проверка без GUI:

```text
py -3.12 tools/test_update_share.py
py -3.12 tools/scan_update_share.py
```

`scan_update_share.py` — список всех версий на шаре и рекомендуемое обновление.

## Проверка и типичные ошибки (результаты проб)

| Симптом | Причина / решение |
|---------|-------------------|
| После обновления процесс в фоне, окна нет | Исправлено в **1.5.3**: нет автоперезапуска — закройте программу и запустите **`ProtocolOOT.exe`** вручную. |
| `Can't find init.tcl` / ошибка Tcl/Tk | Onefile + унаследованные `TCL_LIBRARY`/`TK_LIBRARY`. Сборка **1.5.3** включает runtime-hook; пересоберите exe на **Python 3.12**. |
| `Failed to load Python DLL` (python313/314.dll) | Сборка на слишком новом Python или конфликт `_MEI` в Temp. Собирайте на **3.12**, не переименовывайте папку с **`!`**. |
| WScript / «путь не найден» при перезапуске | Устаревшие сборки с автоперезапуском. В **1.5.3** перезапуск убран — только ручной старт exe. |
| PyInstaller «Failed to remove temporary directory _MEI…» | Нормально при onefile, если антивирус держит файлы в `%TEMP%`. Не используйте **`!`** в пути к папке программы. |
| Шаблоны в `data/` не обновились | Закройте **Word** (файлы docx могут быть заблокированы) и повторите обновление или сборку. |
| Обновление не предлагается | Только **.exe**; проверьте `update_config.json`; версия на шаре должна быть **выше** текущей («О программе»). |
